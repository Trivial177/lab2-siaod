# Лабораторная работа № 2 «Рекурсивные функции, динамический массив, стек и дек»

**Вариант:** 3

## Цель работы

Изучить рекурсивные алгоритмы и влияние мемоизации, реализовать собственные линейные структуры данных, проверить их инварианты и экспериментально показать амортизированную сложность O(1) операции добавления в динамический массив.

## 1. Рекурсивные функции

Реализованы четыре рекурсивных алгоритма:

1) `factorial(n)` — рекурсивное вычисление факториала. Базовый случай: `n <= 1`.

2) `fib_naive(n)` — наивное вычисление числа Фибоначчи. Одни и те же подзадачи вычисляются многократно.

3) `fib_memo(n)` — вычисление Фибоначчи с мемоизацией. Уже найденные значения сохраняются в словаре и повторно не вычисляются.

4) `hanoi(n)` — подсчёт количества перемещений в задаче о Ханойских башнях. Проверяется формула `2^n - 1`.

Для `n = 10` получены следующие результаты:

| Алгоритм | F(10) | Количество вызовов |
|---|---:|---:|
| fib_naive | 55 | 177 |
| fib_memo | 55 | 19 |

Мемоизация значительно уменьшает число рекурсивных вызовов.

## 2. Реализация структур данных

Реализован `DynamicArray` с начальной ёмкостью 4. При заполнении буфера ёмкость увеличивается в 2 раза, элементы копируются в новый буфер. Реализованы операции `append`, `get`, `set` и `len`.

Стек `Stack` построен на основе `DynamicArray` и поддерживает операции `push`, `pop`, `peek`. Соблюдается порядок LIFO: последний добавленный элемент извлекается первым.

Дек `Deque` реализован на двусвязном списке. Поддерживаются `push_front`, `push_back`, `pop_front`, `pop_back`. Операции на обоих концах выполняются за O(1).

## 3. Аналитическая оценка сложности

`factorial` — O(n), так как выполняется цепочка из n рекурсивных вызовов.

`fib_naive` — экспоненциальная сложность, O(2^n): дерево рекурсивных вызовов быстро разрастается.

`fib_memo` — O(n), поскольку каждое значение Фибоначчи вычисляется один раз и затем берётся из словаря.

`hanoi` — O(2^n), число перемещений равно `2^n - 1`.

`DynamicArray.append` — O(1) амортизированно. Отдельное расширение массива требует O(n), но происходит не при каждом добавлении.

`Stack.push` — O(1) амортизированно, `pop` и `peek` — O(1).

Операции на концах собственного `Deque` — O(1). Вставка `list.insert(0, x)` имеет O(n), потому что существующие элементы списка приходится сдвигать. `collections.deque.appendleft(x)` выполняется за O(1).

## 4. Репрезентативные тесты и инварианты

Корректность проверялась функцией `self_check()`. Результат запуска: `self_check: OK`.

Проверены факториал относительно `math.factorial`, числа Фибоначчи, формула Ханойских башен, работа динамического массива через несколько границ роста ёмкости, порядок LIFO для стека и операции дека относительно `collections.deque`.

Основные инварианты:
- для `DynamicArray`: `0 <= size <= capacity`;
- для стека: соблюдается порядок LIFO;
- для дека корректно обновляются начало, конец и размер структуры;
- извлечение из пустого дека приводит к `IndexError`.

## 6. Амортизированный анализ методом учёта

При обычном `append` выполняется запись нового элемента за O(1). Когда `size == capacity`, создаётся буфер в 2 раза больше и существующие элементы копируются, поэтому отдельная операция расширения имеет стоимость O(n).

В банковском методе каждой операции `append` можно назначить условную стоимость 3 единицы: 1 единица оплачивает текущую запись, а оставшиеся единицы сохраняются как «кредит» для будущего копирования при расширении.

Ёмкость изменяется как 4, 8, 16, 32 и т. д. Суммарное число копирований при n добавлениях образует геометрическую сумму:

`4 + 8 + 16 + ... < 2n`.

Следовательно, суммарная работа для n операций равна O(n), а средняя стоимость одной операции:

`O(n) / n = O(1)`.

Таким образом, накопленного кредита достаточно для оплаты редких дорогих расширений, и `append` имеет амортизированную сложность O(1).
